# HTTP fixtures mirror the shim table, and requests join the shared trace

`fixtures/http.json` is the shim table's twin: an array of `{method, url, status, headers, body | body_file}`, `url` a glob over the whole URL, first match wins, identical `(method, url)` entries answering in sequence. There is no request-body matching, because `curl` and `urllib` serialise the same JSON differently; rules check bodies instead. A miss answers `502` with `x-drill-fixture: miss` and a body naming the request. Each request is a line `{method, url, headers, body, status, fixture}` in the shared `.drill/trace.jsonl`, headers lower-cased minus hop-by-hop and proxy ones, and `fixture: null` fails the run. Call matchers gain `method`, `url` (regex) and `status`; rules gain `in-body` (twin of `in-stdin`) and `header` (twin of `env`, regex values); `secret` also checks request URLs, but not bodies or headers, which are a secret's proper channels. Decided in [HTTP fixture and trace format](https://github.com/dworznik/drill/issues/21), prototyped on [`proto/21-http-fake`](https://github.com/dworznik/drill/tree/proto/21-http-fake/proto/http-fake).

To tell which run a request belongs to, drill's scaffold POSTs its workspace path to the fake's `/_drill/run`, and the fake then answers from that workspace's fixtures and appends to its trace. This needs `plugin eval --concurrency 1` (its default). Verified on Linux only.

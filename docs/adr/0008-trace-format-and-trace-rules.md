# Trace format and the `trace-rules.json` vocabulary

The trace is `.drill/trace.jsonl`, one line per call in call order. A shim call is `{bin, argv, env, stdin, exit, fixture}`: `argv` verbatim after `argv[0]`, `env` only the keep-listed variables, `stdin` what was read or `null`, `fixture` the 0-based index of the matched entry or `null` on a miss. Any `fixture: null` line fails the run before the case's rules are read; v1 has no opt-out. HTTP requests share the file (see ADR-0014). No timestamps, cwd or stdout. Decided in [Trace format and assertion rules](https://github.com/dworznik/drill/issues/6), prototyped on [`proto/trace-assert`](https://github.com/dworznik/drill/tree/proto/trace-assert/proto/trace-assert).

Each case's `trace-rules.json` names `calls` (matchers on `bin`, `args` as an argv subsequence, `arg` as a regex on one element, `exit`) and lists `rules`: `order`, `count` with `min`/`max` (`max: 0` means never), `secret` (ADR-0011), `in-stdin <literal> of <call>`, `env {K: v|null} of <call>` and `stop-after <call>`. A rule may inline a matcher and carry a `label`. Secrets are written as literals and masked as `<redacted>` in output; pairing `secret` with `in-stdin` on one literal catches fixture drift. The env keep-list is the variable names the case's `env` rules mention, which the scaffold writes under `.drill/`.

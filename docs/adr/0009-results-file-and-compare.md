# One committed results file per drill, and `compare` over Wilson intervals

A drill writes `results/<UTC-stamp>.json` in the rig, plus a gitignored `results/<UTC-stamp>/` holding raw evidence: each model's `aggregate-result.json` and `report.html`, and every run's `trace.jsonl` and `transcript.jsonl`. The results file stores computed numbers so readers never recompute them: the manifest (skill, drill and rig SHAs with dirty flags; runner and `claudeVersion`; each model and its settings; judge model; run count; date; cost and duration per model; `partial`), for each case × model a run vector with per-run score, error, grader and trace-rule verdicts and drill status, plus c/n, pass rate, Wilson interval, status and the without-skill pass rate; per model the mean pass rate and status counts; per case a content hash of its folder. Decided in [Results schema and `compare`](https://github.com/dworznik/drill/issues/9).

Δ is the with-skill pass rate minus the without-skill pass rate, both by drill's pass rule (ADR-0006); `plugin eval`'s own score delta is left in the raw evidence. `drill compare [a b]`, defaulting to the rig's two newest files, prints a markdown diff keyed by (case, runner, model) and counts a change as moved only when the two Wilson intervals don't overlap; it flags rows whose case hash or skill SHA differ, and also compares two models in one file. No gating or exit codes. `drill table <results.json>` renders the public per-model summary (model, pass/flaky/fail counts, mean pass rate, Δ; skill SHA, date and runner in a footer) with no case names, since held-out cases stay private.
